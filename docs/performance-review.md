# 首屏滚动性能优化（2026-11-05）

用户录屏中的卡顿主要发生在首屏滚动揭幕。上一轮提升画布分辨率后，滚动时仍逐条复制整屏切片，每帧最多调用 301 次 drawImage；刷痕还使用数百条重叠线，增加了绘制开销。

第一轮改为单画布直接绘制背景、银河与文字，以三块填充轮廓完成刷开，取消切片扭曲与离屏画布，并恢复浏览器原生滚动。仍有慢帧，用户反馈依然卡顿，因此继续第二轮优化。

当前实现已删除首屏 Canvas，直接显示横版原始 PNG、文字和静态 SVG 银河。刷痕揭幕简化为 opacity / transform 淡出、位移与分步介绍入场，保留反向滚动还原。支持 `ViewTimeline` 时由浏览器驱动动画，旧浏览器按滚动事件调度 RAF 回退。首屏总高度从桌面 305svh / 手机 275svh 缩短为统一 230svh，减少动态效果模式保留静态单屏。

磁吸效果改为输入唤醒，弹簧稳定且无跟随效果时停止 RAF；取消首屏背景的开场位移动画。地球取消自动旋转，仅在操作或尺寸变化时重绘，地区转动动画在可见时调度 RAF，结束后停止。保留星空首页与 elliothu.me 风格的创作桌面。

## 同环境性能对比

本机无头 Chrome，1440 × 900 视口、2× DPR，等待页面加载后，以 150 个 RAF 步骤控制首屏往返滚动，收集 149 个帧间隔。各轮测量使用相同条件；结果用于比较改动，不保证用户设备或其他浏览器的实际帧率。

| 指标 | 优化前 | 第一轮 | 第二轮（当前） |
| --- | ---: | ---: | ---: |
| 中位帧间隔 | 33.3ms | 16.7ms | 16.7ms |
| P95 帧间隔 | 116.7ms | 50ms | 16.8ms |
| 超过 33.5ms 的帧 | 46 / 149 | 11 / 149 | 0 / 149 |
| 单帧最多 drawImage 调用 | 301 | 1 | 0 |

第一轮在第二轮改动前复测为 10 / 149 个慢帧，P95 仍为 50ms。第二轮扩展验证结果：

- 4× CPU 降速模拟首屏往返滚动：179 个帧间隔，中位 16.7ms，P95 16.8ms，超过 33.5ms 的帧为 0。
- 正常 CPU 整页往返滚动：239 个帧间隔，中位 16.7ms，P95 16.7ms，超过 33.5ms 的帧为 0。
- 页面静止 500ms：没有 RAF 回调或 Canvas clearRect 调用；地球地区转动结束后也停止绘制。这不代表所有 CSS 动画都停止，项目插画仍按设计在可见时摇摆。

上述测量使用程序控制滚动，不能覆盖所有真实输入、GPU 与显示器环境，也不能据此保证全程稳定 60fps。原图约 3.3MB，首次网络加载成本仍存在，本轮未压缩素材画质。

第二轮浏览器回归通过：首屏淡出与介绍分步入场、反向还原、地球地区选择与键盘旋转、创作桌面终端与键盘移动及整理、真实视频预览、项目详情与返回。390px 手机在原生时间轴和禁用 `ViewTimeline` 的回退模式下均通过介绍与回滚、无横向溢出、减少动态效果切换；无 JavaScript 错误。第一轮另已检查原生滚轮和 900px 触屏布局。
